# Engineering Review

Architecture: 画布＋控制双层。图驱动进入、前置视频、对话、控件、提交与退出；画布独立持有背景、视频、立绘、对话四层。ControlNode / BaseNode 的只读基础定义和统一提交保持兼容，控件销毁不清掉画布尾帧。

Code: 新增持久画布控制器与画布命令校验模块，场景适配器只应用图指令。SDK 与类型声明开放四层内容/样式修改和视频事件；AI 生命周期文档明确尾帧衔接和背景切断规则。

Concurrency: 节点访问与媒体代次双重防止过期操作，首帧回调中替换可见视频；暂停、过期及越界资源请求拒绝。画布事件本身不推进图。

Resource: 视频交接最多保留一个可见尾帧和一个待出画视频，替换后释放旧解码器。结局暂停媒体、重开/关闭清理画布，自定义渲染器有 pause/resume/dispose 钩子。无新增依赖，不需 ZIP 或构建分发。

Audit: 进入背景、保持尾帧、首帧接替和控件退出的职责明确；渲染命令不携带目标节点或变量写入。测试可观察四个独立图层与媒体状态。

Verification: 40 项单元测试通过。浏览器验证共 47 项：画布 6、控件桥 6、场景对话 6、MP4/编辑器/独立导出 12、自定义节点 17。通过拦截下一视频请求验证加载期保帧、首帧替换、无视频节点继承、背景切断，同时验证渲染覆写的 pause/resume/dispose 和重新开始清理。测试覆盖编辑器预览、HTTP 独立作品与纯 MP4 的 file:// 导出；报告位于 rusie-film/.test-output，未纳入分发目录。

Risks: 保帧保证运行时不提前清空，不保证素材内容天然连续；AI 仍需用实际尾帧约束分支首帧。刷新不保存解码器或尾帧。组件只经受限接口修改层，任意父页面 JS 不向组件开放。

Decisions Needed: 无。
